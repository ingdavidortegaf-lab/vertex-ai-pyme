-------------------------------------------------------------------------------
1. QUE ES Y CON QUE PROGRAMAS ESTA HECHA
-------------------------------------------------------------------------------

VERTEX AI Pyme es una app movil para tiendas y MiPymes de Casanare: ventas de
contado y fiadas, gastos, abonos, clientes, inventario (con codigo de barras y
productos por peso), reportes con graficas, comprobantes y cotizaciones en PDF
o por WhatsApp, pedidos a proveedores, promociones y un asistente que responde
preguntas del negocio. Todo funciona SIN SENAL y se sincroniza con la nube
cuando vuelve la conexion.

-------------------------------------------------------------------------------
2. ARQUITECTURA: COMO ESTA ORGANIZADA
-------------------------------------------------------------------------------

La idea central es "OFFLINE-FIRST" (primero sin conexion): el celular es donde
se trabaja; la nube solo respalda y comparte datos entre celulares.

   +--------------------------- CELULAR -----------------------------+
   |                                                                 |
   |  lib/ui/      PANTALLAS (lo que ve el tendero)                  |
   |      |  leen y escriben solo en la base local                   |
   |      v                                                          |
   |  lib/data/    DATOS: base local cifrada + cola de envio +       |
   |               servicio de sincronizacion + conexion a la nube   |
   |      |                                                          |
   |      v                                                          |
   |  lib/domain/  REGLAS DEL NEGOCIO (funciones puras, sin pantalla |
   |               ni base de datos): conflictos, formatos, codigos  |
   |               de barras, textos de comprobantes, asistente      |
   +-----------------------------------------------------------------+
               |  HTTPS (solo cuando hay senal y sesion)
               v
   +---------------------------- NUBE -------------------------------+
   |  Supabase: Auth (correo y clave) + PostgreSQL con RLS por       |
   |  empresa + Edge Function "asistente" -> Gemini (IA)             |
   +-----------------------------------------------------------------+

  Regla de oro: las pantallas NUNCA hablan directo con la nube. Todo pasa por
  la base local; la sincronizacion trabaja en segundo plano.

4. COMO FUNCIONA POR DENTRO (ALGORITMOS)
-------------------------------------------------------------------------------

4.1  GUARDAR SIN SENAL (cola transaccional)
  Al guardar una venta, en UNA sola transaccion se escribe:
    - la venta,
    - una salida de inventario por cada producto,
    - una entrada en la cola por cada registro.
  Si el celular se apaga a mitad, o se guarda todo o nada.

4.2  SINCRONIZACION
  Cada 30 s / al cambiar la red / al guardar:
    1. Hay nube? hay red? hay sesion? Si no, la barra lo dice y se espera.
    2. Lee la cola en orden y envia cada registro con "upsert por id".
       - Aceptado: sale de la cola y queda "enviado".
       - Rechazado: espera 15 s, 30 s, 1 min... y a los 5 intentos queda
         "con error" (NUNCA se borra; se reintenta al tocar la barra).
       - Se cae la red: se para; la cola queda intacta.
    3. Descarga lo nuevo de otros celulares desde el ultimo recibido, en
       lotes de 500, y lo une con lo local.
  Garantias: nada se pierde, nada se duplica (cada registro tiene un UUID
  creado en el celular; el servidor ignora un id repetido).

4.3  CONFLICTOS ENTRE CELULARES
  - Ventas, gastos, abonos e inventario: SOLO SE AGREGAN. No hay como
    editarlos ni borrarlos (ni en la app ni en el servidor).
  - Clientes y productos: cada campo guarda la hora de su ultimo cambio;
    al unir gana el mas reciente CAMPO POR CAMPO. Corre igual en el celular
    (conflictos.dart) y en el servidor (triggers merge_cliente/producto).

4.4  INVENTARIO
  El stock NO se guarda como numero: es la SUMA de movimientos
  (entrada +, venta -, ajuste +/-). Asi dos celulares sin senal que venden
  el mismo producto llegan al mismo stock correcto al sincronizar.
  Ganancia = suma de cantidad x (precio - costo) de lo vendido.
  Pedido sugerido = lo que falta para llegar al doble del minimo.

4.5  REPORTES
  Variacion % = (actual - anterior) / anterior x 100, frente al periodo
  anterior de igual duracion (hoy vs ayer, 7 dias vs los 7 anteriores...).
  Si el anterior es 0 se dice "Sin datos para comparar".

4.6  CODIGO DE BARRAS Y GRAMERA
  - Producto empacado: se busca por su codigo exacto.
  - Etiqueta de gramera EAN-13: 2X PPPPP GGGGG C
      2X = prefijo 20-29, PPPPP = codigo del producto en la gramera,
      GGGGG = peso en gramos, C = digito de control (se verifica).
    Se agrega el producto con su peso (gramos -> kg o libras).
  - Sin etiqueta: el tendero escribe el peso que marca la gramera.
  - Un lector USB/Bluetooth funciona porque escribe como un teclado.

4.7  ASISTENTE
  Pregunta -> normalizar (minusculas, sin tildes) -> detectar intencion ->
    si es sobre datos: responde el celular con SQL, exacto y sin senal;
    si es abierta y hay senal: anonimizar -> Edge Function -> Gemini;
    sin senal: resumen local y la pregunta queda en cola.

4.8  COMPROBANTE / FACTURA
  Numero = CV-EQUIPO-000001 (tipo + codigo del equipo + consecutivo,
  asignado dentro de una transaccion; unico entre celulares). Reabrir la
  misma venta conserva su numero. Texto para WhatsApp y PDF con logo
  (tirilla 80 mm o carta), archivado en VERTEX_documentos.
  NO es factura electronica DIAN: tiene los datos (emisor, cliente, items,
  cantidades, precios, total) para conectarlo despues con un proveedor
  tecnologico autorizado.


4.9  CUENTA DE COBRO (FIFO)
  Fiados y abonos del cliente en orden de fecha. Cada abono paga primero
  el fiado mas antiguo. Lo que queda pendiente se agrupa por antiguedad.
  El PDF trae el extracto con el saldo despues de cada movimiento.

4.10 INFORMES SEMANAL / QUINCENAL / MENSUAL
  Del periodo y del anterior: ventas (contado y credito), gastos,
  utilidad, flujo de caja (contado + abonos - gastos), ventas por dia,
  mas vendidos, gastos por concepto, cartera por edades, inventario por
  reponer y libro de movimientos. Sale todo de la base local: sin senal.

4.11 REGISTRO GUIADO Y ADAPTACION
  RegistroGate muestra 5 pasos la primera vez. Las respuestas quedan en
  ajustes (modo_*) y en LocalDb.modo (ValueNotifier): las pantallas se
  redibujan y esconden lo que no aplica.

4.13 MEDIOS DE PAGO Y CIERRE DE CAJA
  Cada movimiento guarda pagos = [{"medio","monto"}] (base local v6 y
  columna jsonb en Supabase). El servidor valida con privado.pagos_validos:
  la suma debe ser igual al monto, medios conocidos y el fiado sin pagos.
  Cierre de caja: efectivo esperado = base + efectivo recibido - gastos en
  efectivo. Detalle: docs/PAGOS_Y_MODELO_DE_NEGOCIO.md

4.14 DESCARGA ADAPTATIVA (para que muchas tiendas no saturen la nube)
  Si no llega nada nuevo, la siguiente consulta automatica espera el doble
  (30 s, 1, 2, 4 hasta 5 min); cuando llega algo vuelve a 30 s. Lo que se
  guarda se sube de inmediato.

4.12 AVISOS
  notificaciones.dart escucha los cambios de la base, espera 2 s y llama
  a revisarAvisos (avisos.dart). Recuerda lo ya avisado en ajustes para
  no repetir. Notificaciones locales: sin servidor ni internet.

  Explicacion completa: docs/CONTABILIDAD_DOCUMENTOS_Y_ADAPTACION.md

5. SEGURIDAD Y DATOS PERSONALES (bases 4.4 y 4.5)
-------------------------------------------------------------------------------
  - Base del celular cifrada AES-256 (SQLCipher); clave aleatoria de 256 bits
    en el Android Keystore. Sin copias de seguridad de Android.
  - Solo HTTPS (TLS 1.2+); la app rechaza direcciones http://.
  - Supabase Auth guarda la clave con hash y sal. Clave robusta: 8+
    caracteres con letras y numeros.
  - Bloqueo de 5 minutos tras 5 intentos; cierre tras 30 min sin uso.
  - RLS: cada consulta en la nube se filtra por la empresa del usuario;
    sin sesion no se lee nada.
  - Secretos fuera del codigo: --dart-define y secretos de Supabase.
  - La IA nunca recibe nombres, celulares ni correos.
  - Ley 1581: autorizacion al primer uso, aviso visible, derechos, revocar
    y borrar. MiPyme = responsable; Gobernacion = encargada.

  Revisar calidad:      flutter analyze
  Pruebas:              flutter test
  APK para el celular:  flutter build apk --release --obfuscate
                          --split-debug-info=build\debug-info
                          --dart-define-from-file=dart_defines.json
  Resultado:            build\app\outputs\flutter-apk\app-release.apk

  VERSION PARA PC (WINDOWS)
  Requisitos extra: Visual Studio Build Tools 2022 con "Desarrollo para el
  escritorio con C++" y el componente "ATL de C++", y el "Modo de
  programador" de Windows activado.
  Compilar:  flutter build windows --release
               --dart-define-from-file=dart_defines.json
  Resultado: build\windows\x64\runner\Release\vertex_ai_pyme.exe
             (copiar TODA la carpeta Release; el .exe necesita sus DLL)
  Diferencias en el PC: la base local es SQLite normal en
  %APPDATA%\co.vertextech\vertex_ai_pyme\vertex.db (en el celular va
  cifrada con SQLCipher); los codigos de barras se leen con lector USB o
  escribiendo el codigo (la camara solo en el celular). La ventana muestra
  la app centrada como en el celular.
  Archivos de Windows: carpeta windows/ (runner/main.cpp pone el titulo y
  el tamano de la ventana).

  Desde VS Code: abrir C:\dev\vertex_ai_pyme, elegir abajo a la derecha el
  dispositivo "Windows (desktop)" o el celular, y presionar F5 (.vscode/).

  Nube: correr supabase_schema.sql en el SQL Editor de Supabase; la funcion
  de IA se despliega con "supabase functions deploy asistente" y su clave con
  "supabase secrets set GEMINI_API_KEY=...".
  Problemas del PC (antivirus, ruta con espacios, NDK): ANDROID_IOS.md.

7. QUE ESTA PROBADO Y QUE FALTA
-------------------------------------------------------------------------------
  Probado: 106 pruebas automaticas; app instalada en Xiaomi 14T; flujo
  completo en modo avion; sincronizacion real con Supabase sin duplicados;
  actualizacion a la version con inventario conservando datos.
  Falta probar en el celular: version con herramientas, codigo de barras,
